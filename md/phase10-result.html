주요 계약

원본은 PNG/JPEG/WebP, 최대10MiB·40MP·단일 프레임이며 기존 320px 썸네일을 별도로 생성한다. 업로드 ticket은 15분·일회성·소유자 제한이다. 계정당 시간당20개 예약 제한을 적용한다. 파일 IO 전에 ledger를 남기며 기존 파일·이력·감사는 물리 삭제하지 않는다.

기록은 업로드 ticket 또는 본인 active 에셋 중 하나를 참조한다. UI 라이브러리는 프로젝트 최종 에셋을 선택한다. 원본 교체는 새 기록으로 분리한다. 이름 변경과 보관/복구는 version 충돌을 검사하며 삭제 요청은 보관으로 처리한다. 원본 조회는 현재 소유권·계정·부모 상태와 checksum을 검사한다. 기존 localStorage 기록은 서버의 실제 탐지 이력으로 가져오지 않는다.

탐지 adapter는 명시적으로 주입하는 서버 계약만 제공한다. 운영 registry에는 등록하지 않았다. 외부 호출 전 dispatch 기록, 공통 큐 제한·동일 기록 진행1개·멱등 요청·lease/cancel/소유자 가드를 사용한다. 응답 불명은 자동 재호출하지 않는다. 출처10개·결과50개·전체metadata64KiB, 결과는 results/empty/partial이고 전체 장애는 failed job이다. 유사도는 null을 허용하며 침해 판정으로 표시하지 않는다.

실행 이력은 jobs에서 20개씩 조회하고 과거 output을 덮어쓰지 않는다. 실패/취소 시 최근 성공 요약을 유지하며 오래된 요청의 늦은 완료는 최신 요약을 역행시키지 않는다. 보관은 queued 취소·running 취소 요청을 기록하고 완료 가드가 결과 연결을 차단한다.

외부 결과는 HTTPS 공개 형식 링크만 허용하고 정규화한 URL의 중복은 거절한다. IP literal·로컬 이름·인증정보·불허 scheme/port를 차단하고 새 창 링크에 noopener/noreferrer를 사용한다. 서버 외부 페이지/이미지 fetch와 DNS/redirect 검증은 구현하지 않았다. 따라서 실제 공급자의 썸네일 수집/SSRF 안전성이나 플랫폼 탐지 품질은 이번 검증 범위가 아니다.

관리자는 추가 인증 후 상세/이력과 공통 작업 페이지에 접근하며 조회 감사도 남긴다. 보관/복구/탐지 요청은 actor·owner를 안정된 순서로 잠그고 비활성 계정을 차단한다. 작업과 감사는 같은 transaction이다. 공급자 미연결 재실행은 503이며 실행/성공 감사 기록을 만들지 않는다.
