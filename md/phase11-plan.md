후속 Phase를 미리 계획하는 것은 허용하되 구현은 번호 순서대로 진행한다. 이전 Phase의 실패·차단·이월 항목이 이 단계의 완료 기준에 영향을 주면 먼저 해결하거나 범위/계약 변경을 기록한다.

## 4. 현재 상태 조사

이번 계획 시점에는 모든 구현이 미착수다. 착수 시 이전 보고서와 실제 코드를 대조해 잔여 mock·권한·번역·배포 문제를 조사한다.

공통 조사 기준은 `feature/backend`의 현재 작업 트리다. 이번 문서 분할 시 `md/`는 기존 미추적 사용자 파일이었으며 원본 규칙을 보존한다. `package.json`에는 `dev/build/start/lint`만 있고 DB·인증·테스트 의존성은 없다. `node_modules/next/dist/docs/`는 현재 확인되지 않았다. 구현 착수 시 설치된 Next.js 버전의 로컬 가이드를 확보·확인한 뒤 코드를 작성한다. 이 문서는 미래 Phase의 코드가 이미 존재한다고 가정하지 않는다. 착수 시 실제 파일, 의존성, 작업 트리 및 이전 결과와 차이를 다시 기록한다.

## 5. 구현 범위

전체 T-01~24 회귀, ko/en UI/메일/공개 업무 번역 누락 제거, 테스트용 제3 언어 추가/배포/게시/활성화, 권한/장애/삭제/부하·실제 공급자 품질, Docker 새 환경·백업/빈 환경 복구·이전 이미지 복원, 운영 문서와 완료 판정을 수행한다.

이 단계에서 추가·변경하는 사용자/관리자 문구는 ko/en 파일 언어팩에 함께 반영한다. 업무 데이터 번역은 `localized_contents`만 사용하고, 고정 UI·랜딩·메일 문구는 DB로 옮기지 않는다.

## 6. 제외 범위

새로운 제품 기능·새 모델·다중 호스트 전환. 운영 배포는 승인된 대상/기존 권한 범위에서만 수행하고, 미승인 시 로컬/검증 환경에서 배포 가능성을 검증한다.

결제·구독, 조직 협업, 범용 CMS, 자동 침해 신고는 전체 초기 범위에서 제외한다. 새로운 비용·제품 정책·공개 계약이 필요하면 구현 전에 전체 플랜과 이 문서의 변경 이력을 갱신한다.

## 7. 결정·가정·질문

출시 대상·배포 호스트·secret 주입·백업 별도 보관 위치/주기·RPO/RTO·부하/비용/품질 상한·번역 검수 담당을 확정한다. 미정 목표를 임의 합격 수치로 만들지 않는다. 출시를 막는 필수 실패는 보류 항목으로 숨기지 않는다.

권장안과 확정 사항을 구분한다. 이 문서 작성에는 추가 승인이 필요하지 않으며, 미결정 항목은 해당 구현의 시작 게이트에서 해결한다. 실제 과금·메일 발송·외부 데이터 변경 검증은 진행 규칙 8.6에 따라 승인된 대상과 환경에서만 수행한다.

## 10. 테스트 계획

기본 검사: `pnpm lint`, `pnpm exec tsc --noEmit`, `pnpm build`. Phase 1에서 제공할 목표 명령은 `pnpm test:unit`, `pnpm test:integration`, `pnpm test:e2e`, `pnpm test:i18n`, `pnpm db:migrate`, `pnpm db:seed`다. 착수 시 실제 스크립트가 존재함을 확인했으며 최종 실행 명령/결과는 체크리스트에 기록했다. 실제 도구/필터 인자는 Phase 1에서 확정하고 착수 시 이 문서와 체크리스트에 실행 가능한 명령을 갱신한다. 테스트가 0개이거나 필수 suite가 skip이면 통과로 처리하지 않는다.

격리된 신규 배포 환경·A/B/관리자·평가 데이터·합의 부하 시나리오·안전한 백업 저장소. 외부 과금/발송 검증은 승인 대상/상한 내에서 수행하며 명령·환경·버전을 기록한다.

## 12. 위험과 대응

이전 Phase PASS는 이후 변경까지 보장하지 않는다. 영향 범위 회귀를 수행하며 부하/복구/공급자 검증을 환경 미준비로 생략하면 완료하지 않는다. 단일 호스트 제약과 외부 커버리지를 운영 문서에 남긴다.

## 13. rollback/복구

신규 요청/worker 획득을 제한하고 마지막 검증 이미지로 복원한다. 호환 migration은 유지/forward-fix, 필요 시 동일 기준 시점 DB+파일 백업 복원 후 핵심 smoke를 실행한다. 실제 복구 시간·손실 범위를 합의 목표와 비교한다.

사용자 변경을 포함한 작업 트리를 통째로 초기화하지 않는다. 적용한 migration과 코드 버전의 호환성을 확인하며, 데이터가 존재하는 환경의 파괴적 되돌리기는 백업/복구 검증 없이 실행하지 않는다.

## 14. 결과 증거와 다음 Phase 인수인계
