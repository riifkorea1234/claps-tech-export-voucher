서버·DB·실행 기반을 구현했다. 실제 인증, 업무 CRUD, 작업 소비, 외부 공급자 연동과 기존 화면의 서버 데이터 전환은 후속 Phase 범위다.

2. 실제 구현

  • Node 22.22.0·pnpm 10.34.5 및 Phase 0 고정 라이브러리를 적용하고 lockfile을 갱신했다. 시스템 pnpm 9.2.0을 교체하지 않고 corepack pnpm을 사용한다. Next 16.3.3의 패키지 내 route handler·server-only·환경변수·standalone·Vitest 문서를 확인했다.
  • Drizzle schema와 최초 SQL migration은 업무/언어 11개 및 인증 3개 테이블을 생성한다. 순환 FK는 테이블 생성 후 추가한다. text ID, timestamptz, 소유자 복합 FK, 활성 가이드의 프로젝트 복합 FK, 이메일/가이드 버전/작업 멱등성/번역 유일성, 목록·큐·감사 인덱스를 포함한다. 삭제 cascade는 없다.
  • Better Auth 1.7.5의 core 모델 필드·타입·필수 여부를 실제 설치 패키지와 테스트로 비교했다. users를 user 모델로 공유하는 authSchema를 제공하며 인증 endpoint는 공개하지 않았다.
  • migration은 전용 연결의 advisory lock으로 직렬화한다. seed는 ko/en 미존재 행만 비활성으로 등록하고 en fallback을 ko로 설정한다. 기존 설정·프로필·권한·게시본을 덮어쓰지 않는다. 개발 fixture는 테스트에만 있다.
  • 서버 전용 lazy DB pool, 환경 검증, 64 KiB metadata 요청 제한, strict Zod 계약, 공통 DTO·pagination·오류 envelope·ko/en 문구·마스킹·서버 발급 request ID·응답 검증 API 클라이언트를 제공한다. 클라이언트의 request ID는 신뢰하지 않는다.
  • GET /api/health는 DB schema 조회 성공 시 data.status=ok, 실패 시 내부 정보 없는 503을 반환한다. 응답은 private/no-store다. worker는 DB 확인 후 heartbeat를 갱신하고 종료 시 제거하며 작업을 소비하지 않는다.
  • Docker는 digest 고정 Node/PostgreSQL 이미지, standalone web, 비관리자 web/worker/migrate, 내부 DB, 공유 uploads 볼륨 및 migration 성공 선행 조건을 제공한다. 테스트 DB는 별도 Compose project/볼륨과 loopback 포트를 사용한다.

7. 남은 위험과 후속 인수인계

  • 기존 UI의 브라우저 저장소와 실제 인증/업무 서버 연동은 아직 없다. 기존 hydration lint 경고 18건은 각 화면의 비동기 연동 단계에서 제거하고, 이미지 metadata 파일의 unused-disable 경고 2건도 정리한다.
  • JSONB DB check는 envelope/버전/크기를 검사한다. 필드별 strict 검증은 서비스가 parseMetadata를 호출해야 한다. 참조 소유권, 전체 locale fallback 순환, 게시 상태 및 worker 완료 전이는 후속 서비스 트랜잭션 책임이다.
  • Phase 2는 비활성 ko/en seed와 messages의 errors namespace를 인수한다. 전체 파일팩 검증 후 언어를 활성화하며 기본 ko 보호·공개 locale registry를 구현한다. 오류 locale header는 현재 최소 계약이다.
  • Phase 3은 authSchema와 core 필드 검증을 인수하되 실제 이메일·비밀번호·세션·권한·CSRF·관리자 정책을 별도로 구현해야 한다. D-01~03은 그대로 남아 있다.
  • Phase 5는 worker 골격을 실제 PostgreSQL jobs 소비기로 확장한다. heartbeat PASS를 작업 처리 성공으로 해석하지 않는다.
  • D-04의 실제 호스트·TLS·별도 백업·RPO/RTO와 D-06~10 공급자/비용/콘텐츠 결정은 해당 Phase 게이트에서 확인한다. 로컬 Compose 재시작은 운영 복구 검증이 아니다.
  • 설치 중 기존 ESLint 9 지원 종료와 Drizzle Kit 하위 esbuild-kit deprecation 경고를 확인했다. 고정 도구는 검증했지만 장기 업데이트는 별도 호환 검토가 필요하다.
  • 운영/실행 안내는 scripts 가이드, DB 변경 책임은 DB 가이드에 있다. Node 22.22.0에서 corepack pnpm install --frozen-lockfile로 재현한다.
