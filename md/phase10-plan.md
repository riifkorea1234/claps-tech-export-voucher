후속 Phase를 미리 계획하는 것은 허용하되 구현은 번호 순서대로 진행한다. 이전 Phase의 실패·차단·이월 항목이 이 단계의 완료 기준에 영향을 주면 먼저 해결하거나 범위/계약 변경을 기록한다.

## 4. 현재 상태 조사

탐지는 홀짝 회차로 목업 8건/0건을 표시한다. 원본 대신 320px 썸네일만 저장하고 연도 없는 날짜·무조건 https 접두사를 사용한다.

착수 조사: Next.js 16.3.3 로컬 Route Handlers 문서 확인. DB/인증/worker/단위·통합·E2E·다국어 테스트와 migration/seed 스크립트가 이미 있다. 현재 작업 트리의 이전 Phase 수정·미추적 파일은 보존한다. 구체적인 기존 구현과 이번 변경 범위는 16절을 따른다.

## 5. 구현 범위

원본/본인 에셋 기준 기록 CRUD·20건 페이지·UTC 시각, 탐지 adapter·출처/URL/썸네일/유사도/발견 시각, 정규화/중복 제거/SSRF 방어, 재탐지 jobs 이력/최근 요약, 어드민 모니터링 상세/재실행·운영 복구를 구현한다.

이 단계에서 추가·변경하는 사용자/관리자 문구는 ko/en 파일 언어팩에 함께 반영한다. 업무 데이터 번역은 `localized_contents`만 사용하고, 고정 UI·랜딩·메일 문구는 DB로 옮기지 않는다.

## 6. 제외 범위

특정 플랫폼 전체 탐지 보장·자동 정기 탐지/알림·신고/삭제 요청·법적 침해 확정. 유사도를 침해 판정으로 표시하지 않는다.

결제·구독, 조직 협업, 범용 CMS, 자동 침해 신고는 전체 초기 범위에서 제외한다. 새로운 비용·제품 정책·공개 계약이 필요하면 구현 전에 전체 플랜과 이 문서의 변경 이력을 갱신한다.

## 7. 결정·가정·질문

허용 검색 API·플랫폼 커버리지·원본 전달 조건·보존/결과 상한·평가/비용/지연을 확정한다. 일부 공급자 장애의 상태/노출과 전체 0건을 구분한다. 공급자 지원 범위에 맞춰 Google/Naver 등 기존 UI 문구를 조정한다.

권장안과 확정 사항을 구분한다. 이 문서 작성에는 추가 승인이 필요하지 않으며, 미결정 항목은 해당 구현의 시작 게이트에서 해결한다. 실제 과금·메일 발송·외부 데이터 변경 검증은 진행 규칙 8.6에 따라 승인된 대상과 환경에서만 수행한다.

## 10. 테스트 계획

기본 검사: `pnpm lint`, `pnpm exec tsc --noEmit`, `pnpm build`. Phase 1에서 제공할 목표 명령은 `pnpm test:unit`, `pnpm test:integration`, `pnpm test:e2e`, `pnpm test:i18n`, `pnpm db:migrate`, `pnpm db:seed`다. 이 스크립트들은 현재 사용 가능하다. 실제 실행/결과는 Phase 10 체크리스트에 기록한다. 테스트가 0개이거나 필수 suite가 skip이면 통과로 처리하지 않는다.

승인된 원본과 공급자 평가 데이터, 중복 URL·불허 scheme·사설/loopback/redirect 목적지·부분/전체 장애·연도 경계·늦은 응답 fixture. 위험 URL은 격리 test double로 검증.

아래는 **실행 전 검증 설계**다. 구현이 끝나면 `phase10-test-checklist.md`에 환경·명령/절차·실제 결과·종료 코드·suite/test 성공/실패/skip 수·실패 원인·수정·재검증을 기록한다. 해당 Phase에 적용하지 않는 테스트 범주는 삭제하지 말고 `NOT_APPLICABLE` 사유와 이후 검증 Phase를 기록한다.

| ID | 필수 여부 | 분류 | 명령 또는 실행 절차 | 기대 결과 | 현재 상태 |
| --- | --- | --- | --- | --- | --- |
| P10-T01 | 필수 | CRUD/권한 | 원본/본인 에셋 기록·검색/페이지/정렬·타인 참조 | 원본 유지·20건 페이지·연도 경계 정상·교차 계정 차단 | PASS — 독립 범위 |

| P10-T03 | 필수 | 통합/장애 | 성공/0건/부분/전체 실패·재탐지·응답 역전 | 상태 구분·실행 이력 보존·최근 요약이 늦은 이전 실행으로 역행하지 않음 | PASS — 격리 adapter |

기본 코드 검사는 코드가 변경되는 Phase마다 필수다. 표의 필수 검증 중 하나라도 `FAIL/BLOCKED/PENDING`이면 완료할 수 없다. test adapter/sandbox 통과와 실제 공급자 품질 검증을 구분한다.

## 11. 완료 조건

- [ ] 실제 원본/에셋으로 탐지하고 4가지 결과 상태를 구분한다.

- [ ] 상세 계획 대비 차이, 변경 파일, 실제 명령·결과 및 이월 항목을 기록했다.

- [ ] 다음 Phase를 막는 미해결 항목이 없다.

## 12. 위험과 대응

공급자 커버리지가 UI 기대와 다를 수 있어 실제 지원 범위를 명시한다. 원본 외부 전달/보존은 확정 정책을 따르며 유사도를 침해의 확정 근거로 취급하지 않는다.

## 13. rollback/복구

신규 탐지/재탐지 등록을 제한하고 이전 adapter로 복원한다. 성공/부분/실패 이력과 원본은 보존하며 중단 작업은 공급자 상태 확인 후 재개한다.

사용자 변경을 포함한 작업 트리를 통째로 초기화하지 않는다. 적용한 migration과 코드 버전의 호환성을 확인하며, 데이터가 존재하는 환경의 파괴적 되돌리기는 백업/복구 검증 없이 실행하지 않는다.

## 14. 결과 증거와 다음 Phase 인수인계

결과 증거: 마스킹된 결과·출처/커버리지·상태별 테스트·재탐지 이력·운영 재실행·SSRF 방어 결과.

다음 단계: [Phase 11](phase11-plan.md)에 전체 실기능·공급자 제약·운영 복구·미완료/회귀 목록과 각 Phase 검증 증거를 전달한다.

구현·검증 후 생성할 파일은 `phase10-test-checklist.md`, `phase10-result.md`, `phase10-result.html`이다. 현재 미생성 파일은 완료 증거로 링크하지 않는다. HTML은 외부 CDN/런타임 JavaScript 없이 단일 파일·반응형·인쇄 CSS로 작성한다. 로그·화면 증거에서 secret, 세션 쿠키, 개인정보, 비공개 원문을 제거한다. MD를 원본으로 삼고 두 보고서에 같은 완료 판정과 수치를 기록한다.

## 16. 2026-09-24 착수 조사와 범위 결정

사용자가 Phase 10 진행을 요청했다. Phase 9 계획·체크리스트·결과 MD/HTML을 확인했으며 독립 규칙 기반 구현은 고유 자동 테스트 147 PASS, 전체 상태는 IN_PROGRESS(실제 파트너 데이터/사업 품질 기준 미제공)다. 이번 요청에 따라 Phase 10 착수 조사와 계획 구체화를 진행한다. Phase 7·8 실공급자 보류와 Phase 9 사업 품질 검수 대기는 유지하며 이전 Phase를 임의로 COMPLETED로 변경하지 않는다.

### 현재 코드에서 확인한 사항

- Next.js 16.3.3의 로컬 Route Handlers 가이드를 읽었다. package.json에는 unit/integration/i18n/E2E, typecheck, migration/seed 명령이 이미 있다. 위 3·4·10절의 미래형 설명보다 이 조사 결과가 우선한다.
- monitoring_records에 소유자·원본 파일/에셋 중 하나·최근 job·최초/최근 탐지 UTC·결과 수·version·보관 컬럼이 있다.
- 사용자 화면은 아직 localStorage, 320px 썸네일, 홀짝 목업 탐지, 무조건 https 접두사를 사용한다. 기존 기록을 실제 서버 탐지 증거로 가져오지 않는다.
- 공통 jobs에는 monitoring 종류와 부모/소유권 가드가 있지만 운영 monitoring handler는 미등록이다. 운영 registry에는 export/matching만 있다.
- 기존 파일 서비스는 PNG/JPEG/WebP 원본·썸네일, 10MiB/40MP/단일 프레임 검증과 IO 전 ledger를 제공한다. monitoring 업로드 target/접근 가드를 확장해야 한다.
- 관리자 monitoring 목록 shell과 공통 작업 감사/재시도는 재사용할 수 있다. monitoring 전용 상세와 실행 연결은 추가 대상이다.
- 작업 트리에 이전 Phase의 다수 수정/미추적 파일이 있다. 이를 보존하고 이번 Phase 관련 변경만 추가한다.

### 사용자에게 제시한 진행 선택

1. 권장: 공급자 없이 기록 CRUD·원본/본인 에셋 연결·실행 이력 계약·관리자 기능부터 구현한다. 미연결 탐지는 503으로 명확히 거절하고 목업 성공을 반환하지 않는다. adapter 계약과 격리 테스트는 실제 탐지 품질 평가와 구분한다.
2. 검색 공급자 비교안을 먼저 작성한다. API 커버리지·원본 전달·보존·결과 상한·비용·평가 조건을 정한 뒤 실연동한다.
3. 사용자가 기존 API의 공급자명과 전달 조건을 지정한다.

공급자와 원본 외부 전달 조건은 아직 확정되지 않았다. 사용자는 아래 16.1절의 독립 구현을 선택했으며 실제 외부 검색·유료 API 호출은 보류한다. 전체 Phase 완료에는 실제 공급자 평가를 포함한 기존 필수 게이트가 적용된다.

### 16.1 확정된 독립 구현 계약

사용자가 2026-09-24 공급자 없는 기록·원본 저장·실행 이력·관리자 기능 구현을 선택했다. 상태 IN_PROGRESS. 순차 게이트 예외는 이 독립 범위에 한정한다.

- 기록은 이름과 원본 upload ticket 또는 본인 에셋 중 하나로 생성한다. 원본 교체는 새 기록으로 분리한다. 이름/보관/복구는 version으로 충돌을 검출한다. 사용자 삭제는 보관이며 파일/이력 물리 삭제 없음.
- 목록은 20건, 리터럴 검색, UTC 생성/최근 순서와 ID tie-breaker. 원본 업로드는 기존 10MiB/40MP/단일 PNG/JPEG/WebP와 15분 ticket, 계정당 시간당 20개 예약 제한을 재사용한다.
- 탐지 요청은 소유권/부모 검사 후 운영 handler 미등록이면 503, job을 만들지 않는다. 이력 조회는 jobs에서 실행별로 페이지 처리하며 기존 결과를 수정하지 않는다. 성공·0건·부분 결과는 bounded schema로 구별하고 전체 장애는 failed job이다.
- 공급자 독립 handler는 명시 주입에만 사용하며 운영 registry에는 등록하지 않는다. 결과 최대 50건/metadata 64KiB, 외부 URL은 HTTPS 공개 호스트만 허용하고 서버가 외부 이미지/페이지를 fetch하지 않는다. DNS/redirect 포함 외부 이미지 수집은 공급자 선정 후 별도 구현·검증한다.
- 관리자 상세에 원본 메타·실행 목록/상태 페이지 연결, 보관/복구·재실행 요청을 추가한다. 추가 인증·소유자 상태·감사 transaction을 유지한다. 미연결 재실행은 503이다.
- 독립 검증: strict 계약/URL·A/B 권한·원본 checksum·보관/복구/version·20건 페이지·미연결 503·불변 실행 이력·늦은 완료 가드·관리자 감사 및 브라우저 ko/en 흐름. 실제 공급자/커버리지·SSRF fetch·운영 품질은 BLOCKED/미구현으로 별도 명시한다.
