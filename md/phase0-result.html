2. 실제 완료 범위와 주요 결정

  • 인증은 이메일·비밀번호 방식이다. 이메일 입력 후 미가입자는 비밀번호 설정·회원가입 화면, 기존 회원은 비밀번호 로그인으로 진행한다. 신규 가입 후 이메일 확인 링크와 프로필 단계를 거치며 비밀번호 찾기·재설정·변경을 Phase 3에 포함했다.
  • lookup은 화면 분기만 제공한다. 가입 여부가 드러나는 사용자 지정 UX를 계약에 명시했으며 계정 ID/상태/프로필은 노출하지 않는다. 최종 가입 시 중복 검사, 비밀번호 검증, 확인/복구 토큰과 세션 폐기를 별도 검증한다.
  • 개인 소유, 조직명은 프로필, PostgreSQL 17.11·Next API·동일 저장소 worker·단일 호스트 Compose와 공유 파일 볼륨을 확정했다. 큐는 PostgreSQL jobs 테이블을 사용한다.
  • Drizzle/pg, Better Auth 이메일·비밀번호/DB 세션, Vitest/Vite, Playwright, Zod, tsx를 선정하고 정확한 버전·공식 근거·peer 범위를 전체 플랜 9.2절에 기록했다. 기존 Node 타입 ^20은 선택한 Vitest와 맞지 않아 Phase 1에서 22.20.4로 변경한다.
  • 업무/언어 11개 테이블에 인증 3개를 추가하고 users를 공유한다. FK·순환 관계·인덱스·JSONB·version/source_revision·멱등성·seed·파일 책임을 구체화했다. 실제 schema 생성/DB 검증은 Phase 1이다.
  • 권한·오류·pagination·locale·상태 전이, 32개 요구사항과 24개 공통 검증 책임, 후속 결정 10건의 담당/기한/차단 조건을 기록했다.

계약 원본은 전체 개발 플랜 5.5·6.6·9.1~9.3·10.3절이다. 작업 범위는 Phase 0 계획을 따른다.

8. 다음 Phase 인수인계

Phase 1 계획에 따라 고정 버전 설치 → Next 로컬 가이드 확인 → DB/schema/migration/seed → 공통 DTO·오류·로그 → Docker·검증 실행기를 진행할 수 있다. Phase 1의 worker는 실행 골격, 실제 PostgreSQL 큐 처리는 Phase 5다. 인증의 실제 화면·서버 동작은 Phase 3 계획을 따른다.

이번 작업에서 Phase 1 구현을 시작하지 않았다. 롤백이 필요하면 이번 4개 수정 문서의 변경 부분과 3개 생성 파일만 대상으로 하며 기존 미추적 사용자 문서 전체를 초기화하지 않는다.
